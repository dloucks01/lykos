# 55 — Adversarial audit of phases 0–4 (2026-10-30)

Goal: before building further, verify the Hypothesis loop (doc 52 steps 0–4) is correct — the
methodologies, the TTPs, and above all the inviolable invariant **false confirmations = 0**. Method:
for every validator oracle, actively try to CONSTRUCT a program that gets a false confirmation; read
each branch; and check each TTP against the SOTA doc 52 cites (Sydr/SAVIOR security predicates,
sanitizer oracles, Shellphish N-run replay, Magma vuln/patched differential).

## Bugs found and FIXED

### F1 — resource-exhaustion false-confirmed an always-slow program (REAL false confirmation)
The timeout oracle confirmed "input runs > 6 s on 3/3 replays" with **no baseline**. A program that is
simply slow regardless of input (a fixed heavy loop) — or any program under heavy host load — was
confirmed as an input-controlled DoS. Reproduced with a 3e9-iteration fixed loop that ignores its
input: `confirmed=True`. **Fix:** differential non-termination — the PoC must hang on every replay
AND a trivial input (`b""`) must return at once. Both runs share the host load, so the differential,
not the absolute timeout, is what is sound. Re-tested: the always-slow program is now rejected
("does not terminate even on a trivial input"); re01/re02 still confirm.

### F2 — cmd-injection could false-confirm on a benign `uid=` / `id` (hardening)
The old order checked the `uid=` OUTPUT marker FIRST and confirmed on it alone. A program that prints
`uid=N(` in a banner, or execs `id` on its own path, would false-confirm. **Fix:** the strace execve
of the injected `id` is now the PRIMARY oracle (the program would not exec `id` on its own); the
output marker is a FALLBACK guarded by a benign control run (confirm only if `uid=` appears on the PoC
and NOT on a benign input). c01/c02/e02 still confirm 1/1.

### F3 — `Hypothesis.from_dict` dropped the `exploit` field (round-trip bug)
`to_dict` wrote `exploit` but `from_dict` did not read it back, so a saved hunt reloaded via
`store.load()` lost its L3 ret2win result. **Fix:** round-trip it. Unit-verified.

## Audited sound — no change needed

- **OOB predicate (stack/heap/global):** flags only when the write END exceeds the object END
  (`hi > obj_end`); writing exactly N bytes into an N-byte buffer is not flagged, N+1 is. No
  off-by-one.
- **int-overflow→alloc predicate:** full-width `UGT(a·b, 2^w−1)` for mul and `(w+1)`-bit add — a
  correct wrap check; the validator confirms via ASan's "allocated by" frame at the alloc line.
- **path-traversal:** the open syscall must carry `../` AND the pinned sentinel, formed from the
  solved input; driver proposes only when input extends a concrete base dir.
- **TOCTOU:** the steady-target guard rejects both a no-check program and a no-race program (if the
  marker surfaces when the symlink is always the target, there is no effective check → declined), so
  only a genuinely winnable check-to-use race confirms.
- **auth-bypass:** secret-swap with a wrong-credential control; always-grant programs are rejected
  ("marker meaningless"), and a legitimate credential cannot match a freshly randomised secret.
- **type-confusion / uninit / mem-leak:** UBSan-vptr / MSan / LSan are sound ground-truth oracles;
  each confirms only at a matched line on 3/3.
- **weaponize ret2win:** the clean-exit-vs-corrupted-return differential; every mis-case (wrong
  byte match, PIE, hanging win) degrades to L2, never a false L3.

## Methodology caveats (documented; lower severity or scaling)

- **native-crash is function-level** (no DWARF line): a multi-bug function could attribute a crash to
  the wrong line. Honest, stated in doc 52. Note: the Tier-0 scorer exercises the ASan branch (source
  builds); the native branch is first stressed at Tier-1 (binaries).
- **MSan on multi-TU targets** false-positives without full instrumentation — a Step-6 scaling item.
- **mem-leak** reports many benign program-lifetime leaks; kept gated off in `hunt` by default.
- **`_same_file` returns True when `hyp.location` is missing** → a line-only confirm could cross files;
  theoretical for `-g` builds (location is set), left as-is to avoid a recall hit.
- **TOCTOU runs the target un-sandboxed** (the race needs host-side symlink swaps) and ignores the
  solved framing — acceptable for an authorized target, weak attribution on multi-open programs.
- **REPLAYS = 3** vs Shellphish's best-accuracy 5; the differential controls matter more than N, but
  5 is a cheap option for the crash/timeout oracles.

## Phase closeout (2026-10-30, follow-up): the coverage gaps worked through

The audit flagged that soundness was verified corpus-wide but phases 0/1/3/4 had test-coverage
gaps. All five were worked through; one uncovered a real functional bug.

1. **Phase 2/3 parser unit tests** — `tests/test_validate_parsers.py` (11 fast tests for
   parse_sanitizer / parse_msan / parse_lsan + the execve/openat regexes against real sanitizer and
   strace output). Caught only unrealistic test fixtures; the parsers were correct.
2. **Phase 0 native-crash oracle** — `bench/tier0/native_check.py` found the native-crash oracle was
   DEAD: `fault_pc` was always None, so it could never attribute a binary-target crash. **Root cause:**
   `batch_runner` only used the ptrace path (which reads the faulting PC) when coverage *blocks* were
   requested; a validation run asks for none, took the untraced fast path, and the crash killed the
   tracee before any PC was read. **Fixed** (256303f): trace when blocks OR a new `fault_pc` flag is
   set; `sandbox.run_batch(fault_pc=)` + `validate._native_runs` pass it. A div-by-zero binary now
   confirms SIGFPE inside its function on 3/3; the fuzzer throughput path is unchanged. This matters a
   lot for Tier-1 (binary targets validate through this oracle).
3. **Phase 1 source-directory hunt** — `bench/tier0/sourcedir_check.py` runs the loop on a 2-file
   Makefile project with the bug in a different TU than main(); confirmed at b.c:5 in parse, mapped
   back to the operator tree. Exercises the two-tree build, multi-file DWARF, and `_display`.
4. **Phase 4 weaponization shapes** — `weaponize_check.py` now covers stdin read-overflow, argv
   strcpy-overflow, and a bounded negative (3/3); the ret2win weaponizer is not overfit to one shape.
5. **Phase 4 / Step 4 B3** — implemented format-string -> %n **write-what-where** (c64a246);
   `bench/tier0/fmt_check.py` 2/2. Step 4 is now complete (B1 ret2win + B3 %n). Two unsound
   confirmation attempts were caught in development (raw output-token diff false-confirming on the
   echoed format string) before the sound behavioural-tail + benign-baseline differential.

Also fixed in this pass: the o02 memory blow-up (OOM) via a memory-pressure prune (f8b8087), and the
store round-trip dropping the `exploit` field (52bfbcc).

## Completeness vs doc-52 exit criteria

- Steps 0–3: proposers emit predicates on lifted IR and the scorer runs with no hand-given sites.
  Full Tier-0 re-measured after the fixes (48 bugs, budget 90 s, `--jobs 6`): **35/48 = 73%
  validated, 0 false confirmations.** The invariant holds across the whole corpus — the central
  result of this audit.
- **Step 2's exit criterion (Tier-0 ≥ 80% validated, 0 false confirmations) is PARTIALLY met: the
  0-false-confirmation half is met; the 80% half is NOT (73%).** The 13 misses are RECALL, not
  soundness, and split into two groups:
  - *memory-cost* — o02 (count-loop) is a genuine regression, NOT contention: re-run in isolation
    (`--jobs 1`, budget 150 s) it still missed and hit the 6144 MB RSS cap at 111 s. Its extra
    directing targets (the `sum/n` division) blow up angr's exploration. A real cost item, not a
    soundness one. (Correction: an earlier draft of this doc wrongly called o02 a contention
    artifact; the isolation run disproved that.) Some PASSES also ran at the budget edge (o05 1/1
    but hit the RSS cap after finding the bug; r04 1/1 at 95 s; p01 1/1 at 94 s), so the config is
    near its limit under `--jobs 6`.
  - *known-hard capability gaps* with documented causes — multi-line protocol input (r02, s05), a
    64 KB input requirement (i02), signed-length (i03), the sprintf-field case (s04), and
    e01/f02/h02/r03. These are the recall work (opt-in `line_fgets`, larger `input_size`), not bugs.

  Net: the 80% gap is RECALL and COST (angr memory/exploration blow-up on o02-style cases), not a
  soundness defect. Closing it is the Step-5/6 reach/trigger + scaling work, not an audit fix.
  So: the loop is SOUND; reaching the 80% bar is a recall push, not a correctness fix.
- **Step 4 is now COMPLETE.** "B1-style → L3 shell" (ret2win, differential-confirmed) and "B3 → %n
  write-what-where" (c64a246, offset probe + 64-bit payload + behavioural-isolation confirmation)
  are both done and regression-checked (weaponize_check.py 3/3, fmt_check.py 2/2).

## TTPs — correct, and where we invented our own

The core TTP chain (static propose → directed solve-the-VIOLATION → replay under a class-correct
oracle → weaponize) matches the SOTA. Where no standard oracle exists we built our own, and the audit
confirms each is now sound: **secret-swap** (auth), **symlink-race + steady-target guard** (TOCTOU),
**baseline-differential timeout** (resource), **clean-exit-vs-corrupted-return** (ret2win). No new
research is needed for the implemented classes. The open research/build items are Step-4 %n
weaponization and Step-5 reach/trigger (CCBSE + hybrid fuzz fallback).
