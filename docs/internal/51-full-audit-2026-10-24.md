## Open (prioritized)
1. ~~Wire `runtime_env` into the live run paths~~ — DONE (f5c224f): discovered once per case
   (dynamic_run, then fuzz before argv discovery), recorded under `<case>/runtime_env/`, adopted
   by every `stage_target`, applied by `sandbox.run`/`run_batch`/`isolate_prefix`, env fuzzing
   and netfuzz; recorded in PoC bundles; surfaced as a run-signal chip. The HTML/PDF/SARIF
   report verdict now says when a target's startup gate was never opened (an execution gap, never
   "No defects demonstrated") and lists the environment that was supplied.
2. **Exploit ladder** (exploit_stage): an unconfirmed ret2win plan gates every later strategy
   (`plan is None`), and several detonators ignore the L2-measured input mode/frame — both lose L3s
   on otherwise-exploitable targets. Several verified-L3 bundles ship reproducers that don't
   reproduce (the live confirm is sound; the artifact is not).
3. ~~`bounds.classify_site` rates a guard larger than the recovered variable but within frame
   headroom SAFE~~ — DONE: now UNKNOWN (the finding keeps its severity). Root cause of the test
   dependency: native (rizin) frames number variables from the frame pointer, but were translated
   with Ghidra's one-word shift, so every x86 frame-pointer copy destination resolved to the
   variable BELOW the buffer (measured on x86-64 and i386 -O0). Native frames now carry
   `coords: "fp"`, honoured on x86/x86-64 (`bounds.frame_offset`); other ISAs are unmeasured and
   unchanged. Disassembly cache version bumped (`ghidra-headless-3`) so stored frames get the tag.
4. `array_index`: x86-64 only; misses function-parameter indices and multi-block -O2 carries.
   * Function-parameter indices — DONE: two passes. Each function records the accesses indexed by
     one of its own parameters (unmodified: a -O0 spill slot with no other writer and no `&`, or
     the -O2 register) with the check it applies, and every call that passes an input value as an
     argument with the caller's check on the way; the join files the finding at the callee's
     access when both checks together still admit an out-of-bounds index (tighter upper bound,
     non-negative if either side proves it). One call level only; a parameter passed on again,
     a constant argument, or a clamped parameter stays silent. Evidence names the caller, call
     site and argument number (`index.via_call`), and each record now carries its own
     `function`/`site` (findings on one global array merge at defect grain).
   * Still open: other ISAs; a register-carried index across more than one edge.
5. ~~Harness replay promotes a finding whenever the whole program crashes on that input, even at a
   different site; the emulator never applies PIE relocations.~~ — DONE:
   * Replay now captures the program crash under ptrace and promotes to `confirmed` only when the
     driven function is on the crashing stack, or (control-flow fault) the program entered the
     function on that input and then jumped to an unmapped pc. Otherwise the crash row is still
     written for root_cause and the finding stays function-level, with the crash site named in
     its evidence. Verdicts go on their own `harness-replay` channel with the run id.
   * Loader, measured worse than noted: with the Ghidra backend a PIE's functions sit at
     0x100000+, the emulator mapped the image at 0, and EVERY driven function faulted on its first
     instruction -> a high-severity "control-flow corruption" per function. Also: lld PIEs keep
     .rodata in page 0 (unmapped by the NULL-page rule -> false OOB reads), lld leaves RELATIVE
     slots 0, and `-fno-plt` calls libc through GOT slots left 0 (false fetch faults at 0).
     A PIE now runs at 0x555555554000 with RELA/RELR relocations applied, imports reached through
     the GOT get synthetic stubs (same libc emulation as PLT calls), and every reported address is
     translated back to the decompiler's coordinates (`load_base` = rootcause.image_base). A fetch
     fault at the function's own entry is never filed. tests/test_harness_loader.py.
   * Note: `rootcause.rebase_delta` is only valid for a PIE (for ET_EXEC it returns the module's
     load address); root_cause tolerates it because it only uses the delta when an absolute match
     fails. Callers that need a runtime shift must treat ET_EXEC as 0.
