     fgetc/read/recv/fread/getline/scanf...) whose result -- in the return register or spilled to a
     frame slot and reloaded -- feeds the terminating comparison, so the trip count is input-/EOF-
     controlled, not a bound on any counter. Wired as `_induction_bound`'s `exit_unbounded` fallback
     (after the constant / input-length / dominating-guard attempts all fail), so it only fires when
     the position has NO bound. Two code shapes:
       (i)  -O0 keeps a SLOT counter. aarch64/arm32 already recognise the load-add-store step; x86's
            `arr[i++]` uses a register-mediated `mov slot,R; lea k(R),D; mov D,slot` increment that the
            direct-`add` detector missed, now recognised by `_x86_lea_incr_steps` (folded into
            `_induction_slots`). The counter indexes the array through a sign extension (`sxtw x0,w0`),
            which the aarch64 scanner now carries through as the index value.

            it is soundly SKIPPED (silent).

     the call graph (`call_names`). Tests test_{x86,aarch64,arm32}_unbounded_input_copy*. (Native rizin

   * PARALLEL bounded counter — DONE (x86 + aarch64 + arm32, -O0). `for(j=0;j<100;j++){ table[i]=j;
     i++; }` -- the exit bounds the counter j, not the array index i, but i advances in LOCKSTEP with
     j (its step is in the SAME block, so both step once per iteration), so i provably reaches
     init_i + step_i * T where T is j's constant trip count (i hits 99 / 104 / 198 for the eq / i=5 /
     i+=2 variants) and overruns -> bound. `_co_induction_bound` fires only when i has NO bound of its
     own and finds a lockstep co-counter j (same `step_block`, now recorded by the slot detectors)
     whose own `_induction_bound` is a CONSTANT; then i_max = init_i + step_i*(j_bound - init_j)/step_j.
     Sound: same-block steps guarantee equal advance counts (a straight-line block runs both or
     neither), and the single-exit gate excludes an early break. p_cond (`if(s[j]) i++`) advances i

     MEMORY OPERAND (mnemonic-agnostic, so `movaps`/`movdqa`/`str q` all count); the byte-offset start
     being past the array's st_size flags `bound`. Two fixes made it fire on aarch64: the equality

   * -O0 slot-path equality exit — DONE (all ISAs): a `for(i=0;i!=C;i++) table[i]` loop terminates on
