8. ~~Static benchmark gate FAILS at `corroborated` (found while checking item 4)~~ — DONE.
   Bisected to f63edb5 (this audit): guard_bound started dropping a guard for ANY store between
   it and the copy, so `if (n > 64) n = 64; memcpy(b, s, n)` -- the commonest safe pattern --
   became an overflow. Underneath was an older unsoundness: a guard counted whenever its safe
   edge dominated the copy, never asking whether the FAILING edge also reached it, so
   `if (n > 64) log(); memcpy(b, s, n)` read as "at most 64 bytes" (a hidden overflow). Now the
   failing edge must not reach the copy except through a clamp (a constant store that satisfies
   the check, followed through P-Code temporaries), and clamp stores do not void the guard.
   Under Ghidra the same benchmark had 5 more false positives (present at c835087 too): Ghidra
   models each PLT stub as a function `memcpy` calling the external memcpy, and that phantom
   site kept every guarded copy corroborated -- `detect.stage.drop_import_stub_edges`. New
   benchmark case `memcpy_guard_logs_only` (bad). Static gate: PASS on both backends (recall
   1.0, fp 0.0, 25 cases).
