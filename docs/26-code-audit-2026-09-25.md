# 26 — Code audit & correctness pass (2026-09-25)

Full-codebase review run as six parallel focused reviews — API/WebSocket server, DB layer,
job engine + process/artifact plumbing, untrusted-input parsers/static analysis,
fuzz/dynamic/debug/sandbox, and poc/link/report/eval/fingerprint. Findings de-duplicated and
ranked by severity. Every item below marked **FIXED** was fixed and validated in this pass
(focused test suites + a 119-test regression sweep + the 131-assertion JS GUI gate; see the
git history for the per-area commits).

> **Owner scope (unchanged from doc 25).** lykos is an authorized, air-gapped, **single-analyst**
> tool; the operator and their inputs are trusted. Findings about the *security of the tool itself*
> — hostile-input-attacks-the-tool/host — are **de-scoped / risk-accepted**: unsandboxed
> build-at-ingest, zip/decompression bombs, RAM-exhaustion DoS from a flooding target, report/
> dashboard XSS (the report path was re-checked and is clean regardless), DNS-rebinding, 500
> exception-repr leaks, path traversal from a malicious *case archive*, and the `./vendor` cwd
> hijack. This pass therefore ranks **correctness, data integrity, robustness on legitimate input,
> and code quality** — anything that makes the tool produce wrong/lost results, crash on real
> input, corrupt state, or rot as code.

## What is solid (rule-outs, for honesty)
- **No SQL injection** anywhere — parameterized throughout; dynamic identifiers whitelisted
  (`TargetDAO._UPDATABLE`), IN-lists build `?` placeholders, LIMIT/OFFSET bound, ORDER BY literal.
- **Report generators are output-safe** — HTML (`esc`/attribute contexts), PDF (`_esc` per line),
  SARIF/JSON (`json.dumps` from dicts). No injection reachable from a malicious binary's strings.
- **Job-queue concurrency core** — per-thread sqlite conns, `BEGIN IMMEDIATE` + status-guarded
  `claim()`, lease/reap, result-discard on lost lease. No `shell=True`/`os.system`.
- **Binary header parsers (ELF/PE/JVM)** — bounds-checked, exception-guarded, attacker counts
  capped; no OOB/crash found on malformed input.
- **Payload/analysis math** — struct widths/endianness, version compare, metrics, cross-taint,
  IPC matching all verified sound.

## HIGH — silently wrong / lost results / data loss

- **FIXED — Distinct sanitizer (SIGABRT) defects collapsed into one finding.**
  `analyze/fuzz/stage.py`, `analyze/fuzz/coverage.py`. The in-memory bucket that *gates* whether a
  finding is filed keyed on `(signal, fault_pc)`; every ASan abort shares one PC, so only the first
  distinct ASan defect became a finding (the rest recorded a `dyn_result` only). Fix: the bucket now
  includes the ASan `defect_key` for SIGABRT (hoisted above the bucket in `stage.py`, added to the
  key in `coverage.py`).
- **FIXED — coverage_fuzz dropped every crash on cross-arch targets.**
  `analyze/fuzz/coverage.py`. `_replay` called `run_batch`/`run_input` without
  `arch/endianness/bits`, so a foreign-arch binary ran natively (rc 127, "not crashed") instead of
  under qemu → AFL crashes discarded. Fix: thread `arch/endianness/bits` through replay + minimize.
- **FIXED — Non-atomic content-store writes → permanent artifact corruption.**
  `casestore.py`. A write interrupted mid-flight left a truncated blob at the final path that
  `exists()` then treated as present forever, so it was never repaired and every future
  integrity-checked read failed. Fix: `_atomic_place` writes to a temp file in the same dir +
  `os.replace`.
- **FIXED — Findings sorted lexicographically by severity.**
  `db/dao.py`. `ORDER BY severity DESC` on TEXT gave `medium > low > info > high > critical`. Fix:
  a shared `_SEV_RANK_SQL` `CASE` expression, applied to `list_by_target` and `list_by_case`.
- **FIXED — Concurrent-migration race → multi-worker startup crash.**
  `db/migrations.py`. Every worker migrates on open; two on a fresh DB both read `have=0` and both
  ran migration 1. Fix: serialize under `BEGIN IMMEDIATE`, re-read the version inside the lock (with
  a lock-free already-at-head fast path), and make `schema_version.version` UNIQUE.

## MEDIUM — correctness / robustness on normal use

- **FIXED — Batched arg-mode fuzzing corrupted bytes ≥ 0x80.** `analyze/fuzz/batch_runner.py`:
  the arg carrier was latin-1-decoded then `os.execv`'d (UTF-8-re-encoded), so the target saw
  different bytes under batching than under the per-exec runner → flaky/dropped crashes. Fix: keep
  raw bytes, build a bytes argv.
- **FIXED — Concolic validation used the wrong-endianness emulator.** `analyze/symbolic/stage.py`:
  `sandbox.run` got `arch` but not `endianness/bits`. Fix: thread both.
- **FIXED — No default job timeout → a hung tool wedged a worker + slot forever.**
  `jobs/config.py`: `default_timeout` 3600s hang-ceiling (matches the longest explicit stage
  timeout, so no long-by-design stage is truncated).
- **FIXED — Worker-id reuse let a stale result overwrite a fresh one.** `jobs/worker.py`: a wedged
  worker and its replacement shared an idx-derived id, defeating the lease-lost guard. Fix: a unique
  per-spawn generation in the worker id.
- **FIXED — Unbounded child-output capture → worker OOM.** `jobs/context.py` and
  `analyze/dynamic/sandbox.py`: `communicate()` buffered the whole of stdout/stderr. Fix: drain both
  pipes concurrently into 16 MiB-capped buffers (stdin fed from a thread to avoid deadlock).
- **FIXED — Orphaned child process groups / unreaped children.** `jobs/context.py`: reap after
  `killpg`, and an `atexit` handler kills tracked child groups on interpreter exit.
- **FIXED — Large multipart upload could silently ingest the framed body.** `api/endpoints.py`:
  when the streamed extractor couldn't locate the file part in a *multipart* body it fell back to
  ingesting the whole framed body (boundaries + headers) as the binary. Fix: `_extract_upload` is
  boundary-aware — falls back to the correct in-memory parse, and 400s rather than ingest raw.
- **FIXED — component_edge upsert duplicated on a NULL symbol.** `db/dao.py`: SQLite treats NULLs
  as distinct in the UNIQUE key. Fix: coalesce `symbol` to `''`.
- **FIXED — `_create_run` 500'd on a nonexistent `target_id`.** `api/endpoints.py`: look up the
  target and 404 before reading `.case_id`.
- **FIXED — Malformed `$LYKOS_CVEDB` override regex aborted the CVE scan.** `analyze/fingerprint/
  scan.py`: guard `re.finditer` per-pattern (skip + log), honoring the documented guarantee.
- **FIXED — SymQEMU ran with no resource limits.** `analyze/symbolic/symqemu.py`: memory/CPU
  rlimits via `preexec_fn`. (Full bwrap containment is de-scoped for this deployment.)

## Deliberately NOT fixed (rationale)
- **Retroactive FKs (`dyn_result.run_id`, `poc.finding_id`, `finding_verdict.run_id`) and the
  migration-12 NOT-NULL seed** — the append-only migration rule plus the table-rebuild required to
  add FKs to existing tables make the risk outweigh the value on a single-user DB (a fresh DB seeds
  migration 12 from an empty `finding` table, so the NULL path is only reachable by an old
  partially-populated DB).
- **ELF Rust/C++ full-file scan cap** — capping the language-marker scan to a prefix risks *missing*
  a marker late in a large binary (mis-detecting the language, which gates detectors); the cost is
  perf-only, so full scan is kept.
- **`_free_port` TOCTOU and batch-tracer grandchild orphans** — negligible on a single-user box; the
  batch runs inside a `--unshare-pid` namespace that reaps grandchildren at batch end.
- **`get_bytes` rehash-on-every-read** — the integrity check is a deliberate safety property, and
  the hot path (`stage_target`) already skips it; with writes now atomic, on-write corruption is
  prevented.
- **Content-hash hex-validation before path build** — this is traversal from a *malicious case
  archive*, which is de-scoped under the single-analyst threat model.
