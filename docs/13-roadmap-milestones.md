Now includes **CFG (basic blocks + edges) and P-Code IR** per function (Ghidra's P-Code = our architecture-neutral IR for the CWE detectors), persisted per function (migration v4) and rendered in the UI (decompiled + disassembly/CFG + P-Code). 67 tests + 1 skipped (real-Ghidra). Now also extracts the **program call graph** (edges with call sites; external/imported callees flagged as taint sinks) and **cross-references** (string references with xref sites), persisted (migration v5, call_edge + string_ref) and served (`/targets/{id}/callgraph`, `/targets/{id}/strings`, callers/callees on function detail) + shown in the UI. 70 tests + 1 skipped. This is the reachability + sink data Phase 3 taint analysis consumes. **RE depth increment (post-hoc): function prototypes + stack-frame recovery.** The Ghidra export script now pulls the *decompiler's* HighFunction (not the coarse listing view): recovered **signatures** (return type + typed params), calling convention/thunk/varargs, and the full **stack-frame layout** — every stack local with its signed offset, size, refined type, and an `is_buffer` flag (so `char msg[64]` is recovered as a 64-byte buffer, not `undefined8`). Persisted (migration v10: `signature` is light/in the function list; `frame_json` — params + frame geometry + vars — is heavy/full view), served (`signature` on the list, `frame` on `/functions/{id}`), and shown in the UI: the function list shows the prototype, and the code viewer adds a signature line, a **stack-frame table** (buffers highlighted) and clickable **caller/callee** navigation. Consumed by a new size-aware detector (`stack_buffer_overflow`, CWE-121): a function that owns a fixed stack buffer *and* calls an unbounded copy (`strcpy`/`strcat`/`gets`/`sprintf`/`scanf`) is flagged with the recovered buffer size and the approximate offset from the buffer to the saved return address — a real exploitation hint. Live-verified end-to-end: `vuln_x86-64` → `greet(char * param_1)` with `char[64]` buffer → *"unbounded strcat() into a 64-byte stack buffer, ~80 bytes to the saved return address."* Architecture-neutral (P-Code/HighFunction), exercised against a multi-arch corpus (`examples/re-corpus/`: 13 architectures of busybox + PE/C++/Rust/stripped/static/UPX variants).

## Phase 3 — Static CWE candidates + findings board
> **PHASE 3 BUILD STATUS (started):** deterministic detection engine — `finding` table with the confidence lifecycle (migration v6) + FindingDAO (upsert/merge), a detector framework + CWE catalog, and three channels: **dangerous-API sinks** (rule), **hard-coded secrets** (string), and **input->sink reachability** over the call graph (approximate taint) that promotes candidate->corroborated. `detect_cwe` stage, `/targets/{id}/findings` + `/findings/{id}` API, and a Detect button + findings list in the UI. Now includes **true intra-procedural data-flow taint** over the P-Code IR (flow-sensitive CFG fixpoint, def-use with kill-on-redefine, per-arch ABI registers) that flags sink sites whose argument registers actually carry tainted data -- more precise than call-graph reachability, and a stronger corroboration channel. Taint is now **inter-procedural**: a summary-based call-graph fixpoint pushes tainted call arguments into callees' parameters and pulls tainted returns back to callers, so a source in a caller reaching a sink deep in a callee (and source-wrapper functions) are caught. 84 tests + 1 skipped. Zero-AI. Remaining: memory/points-to precision (buffer taint via pointers), more CWE families, case-level board UI; **Confirmed** still awaits dynamic/symbolic reproduction (Phases 4/6). **Offline component-CVE fingerprinting (post-hoc): `cve_scan` stage.** Scans a target's bytes for embedded library version banners (OpenSSL/zlib/libpng/busybox/sqlite/curl/expat/dropbear...) and matches a vendored, air-gapped CVE database (`analyze/fingerprint/db.py`), with a version comparator that handles letter suffixes (OpenSSL 1.0.2k) and dotted numerics; each hit is a finding carrying the component, its version, the CVE(s) + CVSS/summary, and the banner that revealed it. For static/stripped firmware this is often the fastest path to a real, known-exploitable bug -- no execution, no fuzzing. The seed DB is curated (high-profile CVEs, ranges best-effort) and extensible: an operator can merge a fuller offline feed via a JSON file at `$LYKOS_CVEDB` (same shape). `resource_class=quick`; UI "CVE scan" button. Live-verified on the corpus: busybox 1.26.2 -> CVE-2021-42374/42378, while 1.35.0/1.37.0 correctly clear.
- Rule + static-taint detectors over IR; CWE taxonomy engine; findings board with the state lifecycle
  (Candidate stage only for now) (doc 05/09).
- **Exit:** produce triaged CWE candidates with evidence for a known-vulnerable test binary.

## Phase 4 — Sandbox + dynamic + debugger
> **PHASE 4 BUILD STATUS (started):** tiered-isolation process sandbox (bubblewrap+netns when available, auto-fallback to rlimits-only + process-group kill), cross-arch execution via qemu-user, crash + timeout detection, a `dyn_result` table (migration v7) + DAO, the `dynamic_run` stage, and `/targets/{id}/dynresults` API + a Run(sandbox) UI control. **A reproduced crash creates a Confirmed finding** (dynamic evidence) -- the confidence lifecycle now reaches Confirmed. 90 tests + 1 skipped; live-verified (SIGSEGV crash -> Confirmed CWE-119). Remaining: integrated debugger, coverage/tracing, binary sanitizers (QASan), stronger isolation (microVM) -- and Phase 5 fuzzing to *generate* the crashing inputs. **Multi-architecture dynamic/fuzzing hardened (post-hoc).** The qemu-user cross-arch path had real routing bugs: the ELF arch name is endianness/bit-blind, so little-endian MIPS/PPC64 were handed the big-endian emulator and RISC-V/S390 were unmapped; `_qemu_for` now routes by endianness+bits (mips→mipsel, ppc64→ppc64le, riscv→riscv64/32, s390→s390x) and endianness/bits are threaded from the target through the sandbox, fuzz runner/campaign, and dynamic stage. Two emulation bugs also fixed: RLIMIT_NPROC was a fixed 256 (below a loaded desktop's live thread count) so qemu's worker threads failed with EAGAIN — now capped at the measured live baseline + headroom; and the exe, staged under /tmp, was masked by bwrap's tmpfs so emulated runs failed silently — bwrap now binds the scratch dir read-only when emulating. Emulated runs get a 3× wall-clock budget and a `+qemu` isolation label. Live-verified on real qemu-user: hand-built aarch64/riscv64/ppc64le ELFs run and their crashes are detected (previously unroutable/mis-routed). **dynamic_run file input mode fixed:** the single-shot dynamic stage silently ignored `input_mode=file` (it handled only stdin/arg/none), so the GUI Run control never delivered a file to a document/image parser -- it now writes the input and passes its path as argv, matching the fuzzer. Verified: a mock file parser crashes on an oversized file via dynamic_run and stays clean on a valid one.
- Tiered isolation (T1 nsjail, T2 microVM), QEMU user/system, Qiling; coverage + tracing; **QASan** sanitizer;
  integrated GDB UI (doc 06).
- **Exit:** safely detonate an untrusted binary, get coverage + a sanitizer-labeled crash, debug it live.

## Phase 5 — Harness + fuzzing (whole-program vectors)
> **PHASE 5 BUILD STATUS (started):** dependency-free black-box mutational fuzzer (seeded RNG havoc mutations + dictionary mined from the target's strings) driving the Phase-4 sandbox over whole-program vectors (stdin/argv/file). Crash dedup, crashing inputs saved as artifacts + dyn_result records, and each unique crash becomes a **Confirmed** finding with its reproducible input (L1). `fuzz` stage, enqueue via `/runs`, Fuzz button + live stats in the UI. 93 tests + 1 skipped; live-verified (fuzz -> SIGSEGV -> Confirmed CWE-119). **Minimizes** each unique crash (ddmin-style chunk removal, budget-bounded) to a tiny reproducer before saving it and building the finding/PoC. **Coverage-guided fuzzing delivered** as an optional **AFL++ qemu-mode** backend (`coverage_fuzz` stage): graceful when AFL++ is absent (locator over LYKOS_AFL/AFL_PATH/PATH, clear error, built-in black-box `fuzz` remains the zero-dependency fallback), harvests AFL's unique crashing inputs and pushes each through the same sandbox->minimize->dedup-by-signal-> Confirmed-finding pipeline; Coverage-Fuzz button + live stats in the UI; 107 tests (+2 skipped incl. the real-AFL run, skipped here since afl-fuzz is not installed). **Directed fuzzing at static candidates delivered** (`directed_fuzz` stage, zero dependencies): ranks the addressed static findings as targets (taint/reachability-corroborated dangerous sinks first), computes AFLGo-style backward callgraph distance to each, and mines a targeted dictionary + seed corpus from the string constants the near-target functions actually reference in their P-Code (resolved via each string's xref sites), biasing the shared `fuzz_campaign` toward the sink; degrades to an undirected string-mined campaign (and says so) when no static graph exists, e.g. Ghidra absent. Directed-Fuzz button + live target/dictionary readout in the UI. 116 tests (+2 skipped); live-demonstrated advantage: with 400 decoy strings and a 600-exec budget, undirected found 0 crashes while directed reproduced the token-gated crash. **Seed-corpus attachment in the UI (post-hoc):** the Dynamic & fuzzing stage gained a "+ seeds" file picker -- the analyst attaches valid sample files (base64'd client-side into `params.seeds`), which all three fuzzers (black-box, coverage/AFL++, directed) already accept, so the mutator starts from real structure. This is what makes file-format parsers (PDF/image/doc) fuzzable: without a seed a mock IMG parser found 0 crashes, with a valid seed the fuzzer found thousands and produced a file PoC whose input.bin is the malformed file. **Structure-aware mutation layer delivered (post-hoc):** a seed alone still leaves byte-level havoc unable to *coordinate* related fields -- it corrupts the magic and cannot grow a length-prefixed blob to match the length integer that sizes it (the classic length-driven overflow). `fuzz/structure.py` adds a data-described format model (`FormatModel`: ordered field dicts -- magic / u8..u64 with optional `length_of` / trailing blob) and a `StructMutator` with the byte Mutator's `mutate(data, corpus)` interface: it parses the input, mutates 1-3 fields while keeping the magic gate intact (kept 92%), drives integer fields to edge values (0/off-by-one/huge), and when a field is `length_of` a blob, coordinately grows that blob to the new length -- and falls back to byte havoc on any parse/serialize failure. Ships built-in models (`lv32` magic+u32-LE-length+payload, `png` signature+chunk-length+IHDR) and accepts an analyst's custom spec; magic is overridable (`params.magic`) to pass a specific format gate. Wired into both the black-box `fuzz` and `directed_fuzz` campaigns via `fuzz_campaign(..., mutator=)`, with a UI format-model dropdown + magic override next to the seed picker. Live-demonstrated decisively: on the same mock IMG parser + valid seed in a 400-exec budget, byte-level found **0** crashes while structure-aware found **120** (unique length-driven overflow). A GUI **custom-format spec builder** (post-hoc) makes the model buildable without knowing the raw bytes: `POST /format/analyze` either suggests a starting spec from a real sample — detecting the magic and auto-finding the length field by matching an integer to the trailing byte count — or, given a spec, carves a sample with the *actual* fuzzer parser and reports per-field offset/size/value, whether each length field matches the real blob size, and roundtrip fidelity. The builder modal edits fields visually (magic/u8..u64/blob, endianness, length-of links, ascii/hex magic) with a live truthful preview, then feeds `params.format` to the campaign. A runnable end-to-end demo ships in `examples/pdf-structure-fuzz/` (mock `%PDF` parser + valid seed + the fuzzer's minimized crashing input): on the same seed and 400-exec budget byte-level found 0 and structure-aware (`format_name=lv32`, `magic=%PDF`) found 137, confirmed CWE-119. Remaining: LibAFL composable engine; hybrid concolic is Phase 6.
- Input-vector discovery; whole-program harness gen; seed/dictionary mining; LibAFL/AFL++ campaign with live
  dashboard; crash feed → **CASR** triage/dedup/minimize (doc 07/08).
- **Exit:** auto-harness a file/stdin target, run a campaign, get deduped minimized crashes on the board.

The stage seeds angr with the fuzzer's corpus (the hybrid handoff), solves path constraints toward the statically-flagged sink sites (from `select_targets`), and emits concrete inputs; every generated input is then **replayed in the Phase-4 sandbox** so a crash becomes a Confirmed finding (detector `concolic`), a reached sink promotes the static finding to **corroborated** (a `symbolic` evidence channel), and the rest become new seeds handed back to the fuzzer. Locator over LYKOS_ANGR_PYTHON / a vendored venv / python3 (each verified by importing angr); clear failure when absent, with fuzzing as the deterministic fallback. It detonates a De Bruijn cyclic pattern under a pure-stdlib **ptrace** register/stack-capture helper (`poc/ptrace_capture.py`, run as its own process so it never forks the threaded worker), recovers the control offset from the return-address slot the stack pointer indexes at the `ret` fault (robust to non-canonical addresses that make the PC report the ret site), then **confirms** by placing a canonical sentinel at that offset and checking the program counter loads it. The report is stored as an artifact and a root-cause evidence line is attached to the crash finding; Root-Cause button + live summary in the UI. Native-arch only (cross-arch reported unsupported). 142 tests (+3 skipped); live-confirmed: a stack overflow is explained as CWE-121 at a `ret`, a null write as CWE-476 via `mov eax,[rax]`. **Crash exploitability rating (post-hoc):** the root-cause report now carries a !exploitable/CERT-triage-style verdict (`debug/exploitability.py`) derived from the classification -- EXPLOITABLE (control-flow hijack, saved-return overwrite, illegal instruction, or a write to an attacker-looking address = write-what-where), PROBABLY_EXPLOITABLE (generic write AV, or a stack-canary/FORTIFY/heap abort), PROBABLY_NOT_EXPLOITABLE (read AV / NULL deref), NOT_EXPLOITABLE (div-by-zero DoS), with a 0-100 score and reasons; the crash finding title gets the rating and an exploitability evidence line, and it rides the rootcause.done event/UI. Zero-AI rules over signal + faulting instruction + fault address. **SymQEMU delivered as an alternate concolic backend** for the `concolic` stage (params.backend = auto | angr | symqemu): a QEMU-based, source-free concolic engine seeded by the fuzzer corpus that flips branch conditions along the concrete path and writes new inputs (SymCC interface: SYMCC_INPUT_FILE / SYMCC_OUTPUT_DIR), iterated for a few rounds; located per-arch (LYKOS_SYMQEMU / vendored / PATH `symqemu-<arch>`). Live-verified: the shipped `exploit.py` re-hijacks to win() across repeated runs under fresh ASLR. 291 tests pass. **Static stack-frame recovery feeds L2 offset recovery (post-hoc).** The recovered stack buffers (see Phase 1 RE deepening) now predict the instruction-pointer-control offset — in Ghidra frame coordinates, `ret_offset - buffer_offset` (the distance from the buffer to the saved return address) — via `primitive.frame_offset_candidates`. The `poc_primitive` stage uses these two ways: (1) **corroboration** — when the dynamic cyclic offset matches a predicted one, the L2 finding names the buffer (e.g. *"offset 136; corroborated by static stack frame — 128-byte buffer local_88"*), and the cyclic pattern length is sized to cover the largest prediction; (2) **static-seeded confirmation** — when the dynamic slot heuristic can't pin an offset (noisy fault, not a clean `ret`), each predicted offset is tried directly (place the sentinel, re-detonate, check PC==sentinel), so IP control can be proven from the static frame plus one confirming run. Verified symbol-independent (a **stripped** PIE build recovers the same frames and offset, buffer just named `local_88`) and **cross-architecture**: an **aarch64** static-PIE build (built with a musl cross toolchain, run under qemu-user) confirmed IP control at offset 136 via the qemu-gdbstub L2 path. Corpus gained `vuln_aarch64`.
